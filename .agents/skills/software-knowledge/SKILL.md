# Software knowledge

Start with the [knowledge index and workflow](../../../docs/software-knowledges/README.md).
Open only the sections the request touches:

- [System](../../../docs/software-knowledges/system/README.md) for product scope, actors, or responsibility boundaries.
- [Goals](../../../docs/software-knowledges/goals/README.md) for user outcomes and success criteria.
- [Flows](../../../docs/software-knowledges/flows/README.md) for behavior, handoffs, and recovery.
- [Artifacts](../../../docs/software-knowledges/artifacts/README.md) for models, rules, and the receiving part's contract.

Use those documents as the source of truth; do not duplicate their workflow or
templates. Keep unresolved decisions explicit instead of inventing defaults.
For an explanation-only request, read the relevant sources and answer without
editing files.
